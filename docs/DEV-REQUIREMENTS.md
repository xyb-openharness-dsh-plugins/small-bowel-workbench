# DEV-REQUIREMENTS · small-bowel-workbench

版本 0.1.0 · 2026-11-14 · 状态：M0–M3 开发日草案，**未经用户签认、未经临床审核**。

本文件是本仓硬约束的唯一入口。与家族通用文档冲突时，以本文件与用户当次指示为准。

## 一、四条总原则

1. **患者视角优先**：页面按患者要带去门诊的东西组织（确诊依据、病理、影像、用药、症状、营养、复诊），不按医院科室表单组织。
2. **记录不等于判断**：本台只整理资料与就诊准备，不做诊断、不判分期、不判复发风险、不评疗效、不给治疗建议。
3. **没有实测不写通过**：`npm run check` 只是 V1；V2 装机、V3 业务实测未做前，报告必须写「未验证」。
4. **合成数据唯一来源**：演示数据只来自 `dsh/demo.js`，全部 `is_demo=1`，界面常显「合成示例」。

## 二、疾病语义红线

- 全站（`public/`、`src/`、`dsh/`、`lib/`）禁词：**预后、生存期、疗效、治愈率、五年生存率、复发风险**。
- 不出现「建议化疗 / 应该手术 / 必须复查」等指令式结论；只呈现「医生原话」「计划」「已完成」。
- 分期、分级、切缘、分子结果只以 `*_text` 原话保存；界面标题写「医生记录的分期」，不写「你的分期」。
- 任何阈值、复查间隔、警示文案均为【待核】占位。
- 明确边界：本台收录**小肠原发腺癌**；壶腹部癌、胰胆来源、淋巴瘤、GIST、神经内分泌肿瘤不属于本台范围，界面需说明。

## 四、数据层纪律

- 迁移只增不改；`0001` 冻结后只能新增 `0002+`。
- 所有裸查询 `ORDER BY rowid`；未知值用 `NULL`，不用空串。
- 化验按 `method_text + org_text` 分组；不同方法/机构不合并、不连线、不做差。
- 分类字段（病理类型、影像模态、治疗类别）不进趋势图。
- 无 `diagnosis` / `risk_level` / `activity_score` / `prognosis` / `response` / `line_of_therapy` 列。
- 删除档案：演示档案禁止删除；真实档案删除前二次确认（M4 实现 UI）。

## 五、DSH 接入约束

- `dsh/index.js` 必须导出 `name` / `inject` / `Config` / `apply`；`Config` 用宿主提供的 Schemastery，且只在入口出现。
- 自带 API 只用 `/api/small-bowel/*` 前缀；宿主形态必须调用 `ctx.connection.requestRejection(req)`，缺失能力返回 503，不绕过鉴权。
- `cordis.patch.yml` 的 `insert.name` 是完整 npm 包名。
- 客户端 `customFrame: true`、`businessSide: 'left'`、`businessWidth: 0.65`，参数唯一来源 `lib/layout.js`。
- 业务界面全部在 `public/`，宿主外壳只放 iframe；不在客户端重画第二套业务 UI。
- 原生会话始终挂载，只以 `display` 控显隐；不得卸载导致草稿丢失。
- 不覆盖宿主导航、设置、窗口按钮；macOS 顶栏避让由宿主外壳负责。
