# SPEC · 小肠腺癌患者工作台 v0.1（M0–M3）

## 1. 范围

首版覆盖「确诊后资料整理 + 就诊准备」。不含在线问诊、处方、医保结算、病友社区。

## 2. 信息架构

| 页面 | 患者问题 | 首版内容 |
| --- | --- | --- |
| 今天 | 我现在最该看什么？ | 档案摘要、最近记录、待整理资料、就医红旗占位、快捷入口 |
| 档案 | 我到底是什么病？ | 原发部位、病理类型、医生记录的分期/分级、确诊依据、分子检测原话 |
| 检查 | 最近变化在哪？ | 化验按方法+机构分组、影像时间线、报告原文入口 |
| 治疗 | 我做过什么、在用什么？ | 手术/系统治疗/放疗时间线、当前用药、疗程原文 |
| 症状与营养 | 我哪里不舒服、吃得怎样？ | 症状自述与自评、体重曲线、进食与补充剂记录 |
| 随访 | 下次要做什么？ | 医生已安排的复诊/检查、已完成状态、材料清单 |
| 试验 | 有没有可问的临床研究？ | 收藏的试验、检索通道状态（未接通时明确写） |
| 资料 | 原始材料在哪？ | 文档清单、类型、来源路径、解析状态（未接通） |

## 3. 交互原则

- 首屏先给「能带走的东西」，不是仪表盘堆图。
- 每个数值旁保留单位、参考范围原文、方法与机构；缺一项就显式写「未记录」。
- 趋势只对同一 `method + org` 的同一指标连线；不足两点不画线。
- 所有日期用 `YYYY-MM-DD`；未知显示「未记录」，不猜。
- 错误用横幅 + 重试按钮，不白屏。

## 4. 核心对象

`subject`（档案）→ `diagnosis` / `pathology` / `lab` / `imaging` / `treatment` / `medication` / `symptom` / `nutrition` / `followup` / `document` / `saved_trial` / `viewpoint`。

全部事实表挂在 `profile_key` 下；演示档案 A/B 与真实档案同构，只用 `is_demo` 区分。

## 5. 数据流

```
public/app.js
  → GET /api/small-bowel/bootstrap
  → GET /api/small-bowel/read/<entity>?profileKey=...
  → 渲染

dsh/index.js (宿主) / scripts/serve.mjs (独立)
  → dsh/server.js (认证、路由、静态、错误)
  → dsh/workbench.js (档案、写入、隐私)
  → dsh/readmodels.js (只读查询)
  → node:sqlite
```

## 6. 非功能

- 单机、离线可用；无遥测、无外链字体。
- 首屏 JS 不超过 1200 行，CSS 不超过 900 行（M3 骨架约束）。
- 页面容器宽度自适应 360–1600px；窄屏单列，导航可横向滚动。
- 所有交互目标 ≥ 40px 高；正文 ≥ 15px；支持 `prefers-reduced-motion`。

## 7. 验收（M3）

- 八页可切换，hash 可回放。
- 演示 A/B 切换后页面数据完全换一套。
- 空档案显示空态，不显示上一档案残留。
- 私密记录不出现在摘要、导出与 AI 上下文。
- `npm run check` 全绿。

## 8. 非目标

- 不做分期计算器、复发风险模型、疗效评估、生存分析。
- 不做药物相互作用检查。
- 不做指南全文镜像。
